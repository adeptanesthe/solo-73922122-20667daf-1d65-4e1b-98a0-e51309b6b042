# 再生塑料配方试配筛选（质检模型 + 最优改配求解 + 容差核查）

面向再生塑料配方研究员与生产工程师的网页工具，包含两个相互独立的工具（页面顶部标签切换）：

1. **试配求解**：录入原配方与各原料的上下限、锁定项后，在**合格概率 ≥ 0.7** 的约束下，
   按 **先最少改变原料种数、再最小化总克数改变量** 的字典序求出最优试配方案；
   只有求解器**证明**无解才报无解，求解失败单独报告。
2. **容差核查（投产放行）**：录入总重 1000 克的整数基准配方、各原料允许偏差（整数克）
   与锁定项，在称量误差容差域内的**全部**可行配方（总重仍为 1000、用量非负、锁定量不变）中，
   按现有随机森林的 float32 推理语义求**最低合格概率**及对应配方，并用原分类器复算。
   最差概率经证明 ≥ 0.7 才显示**可放行**；已证实低于阈值时显示**不合格反例**；
   求解未能判定则保持**待判**，绝不臆断。

## 技术栈与模型

- **FastAPI** 提供网页与 JSON API；**scikit-learn** 训练随机森林；**z3-solver** 求解。
- 质检模型：`RandomForestClassifier(n_estimators=5, max_depth=3, random_state=20241117)`，
  在固定种子生成的合成数据上训练（Dirichlet 采样的配方比例 + 含噪质检规则，阈值取中位数
  使类别均衡）。每次启动以同一种子重训，结果确定（自测第 1 项验证同种子重训一致）。
- 配方为 4 种原料的整数克数，总重 1000 克；模型输入为克数 ÷ 1000 的 **float32** 比例。

## 求解语义（与分类器严格一致）

- sklearn 树内部以 float32 特征与 float64 阈值比较。求解器把每个分裂条件
  `float32(g/1000) <= τ` 预计算为等价的**整数截断** `g <= K`（`app/model.py: cutoff_left`），
  因此 z3 中的约束与原分类器的实际阈值语义逐点一致（自测第 2 项对全部阈值 × 0–1000 克逐点核对）。
- 森林概率 = 5 片叶子概率（精确有理数）之和 / 5 ≥ 0.7，以精确有理数编码进 z3。
- 字典序优化用**两阶段**实现：先最小化改动种数，固定该最优值后再最小化总改动克数。
- 每份建议解出后**用原 sklearn 分类器复算概率**（float32 输入），未通过复核则按求解失败上报，
  绝不当作合格建议展示。
- 结果状态严格区分：`ok`（已证明最优）/ `infeasible`（z3 判定 unsat，即证明无解）/
  `invalid`（输入不合法）/ `solver_failure`（z3 unknown、超时或异常，**不**当作无解）。

## 容差核查语义（投产放行）

- 容差域：`g_i ∈ [max(0, base_i − tol_i), min(1000, base_i + tol_i)]`，锁定项退化为
  单点 `g_i = base_i`，并要求 `sum(g_i) = 1000`、`g_i ≥ 0`。基准配方总重为 1000 且偏差为
  对称闭区间时，基准自身恒在域内，故合法输入的容差域必然非空（自测以 5000 组随机输入验证）。
- 求解器在该整数域上以 z3 `Optimize` **最小化**森林平均合格概率，编码与试配求解共用
  （`app/forest_enc.py`），同样严格遵循 float32 特征 vs float64 阈值的真实分裂语义，
  叶子概率为精确有理数。
- **可判定口径**（缺一不可，任一不满足一律报 `pending` 待判）：
  1. z3 返回 `sat` 且最小化目标的上下界严格相等（最优值已证明，而非近似）；
  2. 最差配方确实落在容差域内、总重 1000、锁定量不变；
  3. 精确有理概率与原 sklearn 分类器 float32 推理复算值一致（容差 1e-12）；
  4. 有理侧与浮点侧对“是否 ≥ 0.7”的判定一致。
- 结论三态：`pass`（已证明最差概率 ≥ 0.7，可放行）/ `fail`（已证实不合格反例，且该反例
  被证明是域内概率最低点，不可放行）/ `pending`（超时、unknown、界未收敛或复核不一致，
  保持待判，不得据此放行或拒收）；输入本身不合法为 `invalid`。
- 响应同时给出：最差配方及其原分类器复算概率、精确有理概率（分子/分母）、基准配方概率、
  容差域可行配方总数（前缀和 DP 统计，自测对全单纯形组合数与随机小域暴力枚举双重核对）、
  逐原料基准/最差/偏差/允许区间明细、可机读的最优性结论文本。
- **并发安全**：z3 底层 C++ 运行时非线程安全，服务端以模块级 `SOLVER_LOCK` 把所有求解路径
  串行化；自测含 8 路并发回归（无锁时 z3 会进程级崩溃）。

## 运行

### Docker Compose（推荐）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

### 本地开发

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## 页面与交互

- 顶部两个标签页：**试配求解**与**容差核查（投产放行）**，各自独立维护请求代次（epoch），
  切换标签或在一个工具内修改都不会撤下另一个工具的结论。
- 试配录入：4 种原料的原配方克数、各自下限/上限、锁定勾选；总重须为 1000 克。
- 容差录入：4 种原料的基准配方克数、各自允许偏差（±克）、锁定勾选；区间列即时显示每个原料
  实际允许的整数区间，基准总重即时校验。
- 「载入可行样例」「载入无解样例」「载入放行样例」「载入不合格反例样例」：样例在服务启动时
  由真实模型 + 求解器**实测验证**后生成（`app/samples.py`）。
- **计算期间可随时修改**：任何输入修改会立即撤下当前工具的旧结论（清空结果区）、中止在途
  请求；迟到的旧响应按 epoch 比对后直接丢弃，不会恢复显示（`app/static/index.html`）。
- 容差结果展示：可放行（绿色，含最差配方与最低概率）/ 不合格反例（红色，含反例明细与
  最优性依据）/ 待判（蓝色，明确提示未取得证明前不得放行或拒收）/ 输入不合法（灰色）。

## API

| 端点 | 说明 |
| --- | --- |
| `GET /` | 单页网页（含两个工具标签页） |
| `GET /api/meta` | 模型规格（树数、深度、种子、阈值、特征名） |
| `GET /api/samples` | 经求解器实测的可行 / 无解 / 容差放行 / 容差反例样例 |
| `POST /api/solve` | 试配求解；体：`{original, lower, upper, locked}`（各 4 元） |
| `POST /api/tolerance` | 容差核查；体：`{base, tolerance, locked}`（各 4 元），返回 `pass` / `fail` / `pending` / `invalid` |

## 完成说明（据实）

**已实现**

- 试配求解原有全部功能保持不变：合成数据 + 固定种子随机森林（5 棵树、深度 ≤ 3）；
  z3 按原分类器真实阈值语义编码（抽取为共用模块 `app/forest_enc.py`，试配与容差共用）；
  两阶段字典序最优求解；每份建议用原分类器复算；四种结果状态严格区分。
- 新增**容差核查**完整链路（`app/tolerance.py` + `POST /api/tolerance` + 页面第二个标签页）：
  容差域整数建模、z3 `Optimize` 最小化森林概率、严格的证明/待判口径、原分类器 float32
  复算与精确有理数双重核对、pass/fail/pending/invalid 四态、容差域配方数 DP 统计、
  放行/反例两组启动实测样例。
- 前端两套工具各自独立 epoch + AbortController：修改即撤下本工具结论、迟到响应不恢复、
  两工具互不干扰；区间即时计算与总重即时校验。
- 修复一个并发稳定性问题：z3 非线程安全，FastAPI 线程池并发调用会导致进程崩溃，
  已用模块级 `SOLVER_LOCK` 串行化全部求解路径并加并发回归测试。
- Docker Compose 交付物沿用原配置（依赖未变，z3-solver 已在 requirements 中）。
